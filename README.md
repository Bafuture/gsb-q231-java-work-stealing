## 实现说明（分支 A）

源码位于 `src/main/java/com/example/gsb/scheduler/`：

| 类 | 职责 |
|----|------|
| `WorkStealingScheduler` | 调度器入口：提交、依赖、动态伸缩、静默等待、失败收集 |
| `Worker` | 工作线程循环：本地取头部 → 扫描窃取尾部 → 退让 park |
| `WorkStealingDeque` | 每线程双端队列：头部 LIFO（本地）、尾部 FIFO（窃取） |
| `Task` / `TaskHandle` | 内部任务表示与外部句柄（join / 错误查询） |
| `TaskFailure` | 失败任务收集记录 |
| `FixedAssignmentScheduler` | 固定分配对照组（负载对比基准） |

设计要点：

1. **窃取协议**：本地提交/取用走队列头部（LIFO），窃取者从尾部取最老任务（FIFO），降低竞争。
2. **空闲退让**：本地为空 → 随机起点扫描全部队列窃取 → 仍空则先 `yield` 若干次，
   再按指数退避 `parkNanos`（上限 1ms），提交时 `unpark` 唤醒，绝不忙等。
3. **动态伸缩**：`resize(n)` 在全局 `resizeLock` 下进行；缩容时被移除线程标记
   `retiring`（不再接收新任务、不再窃取），其队列剩余任务原子转移到存活线程，保证不丢失。
4. **恰好一次**：任务只可能存在于一个队列或被一个线程执行；依赖就绪、入队、
   缩容转移全部在锁保护下完成，测试用计数器验证不重不漏。
5. **异常隔离**：任务异常被捕获并收集到 `failures()`，worker 循环继续处理后续任务。
6. **依赖顺序**：`submitAfter` 的后续任务 pinned 到前驱的 home worker，
   即使前驱被窃取执行，后续任务仍回到正确线程且不会被再次窃取，保持本地顺序语义。

负载不均对比（4 worker，4×250ms 重任务全部轮询落入 worker0 + 24×5ms 轻任务）：

```
固定分配完成时间: ~1015 ms
工作窃取完成时间: ~290-310 ms
加速比: ~3.3-3.5x
```

## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的大任务会被拆成大量小任务，固定分配会导致部分线程早早空闲、部分线程排队严重。请从零实现一个工作窃取任务调度器。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 每个工作线程维护自己的双端队列，提交到本线程的任务从头部取，空闲线程从其它线程尾部窃取；2) 空闲检测：线程本地队列为空时按策略尝试窃取，全部为空后按退让策略等待，不得忙等占满 CPU；3) 支持工作线程数量动态调整（增加与减少），减少时要保证被移除线程的未执行任务不丢失；4) 正确性：任意任务图下所有提交的任务必须恰好执行一次，需用计数器验证不重不漏；5) 支持任务抛异常：单个任务失败不得影响其它任务执行，失败任务要能被收集；6) 支持依赖任务：被窃取执行的任务其后续任务要回到正确线程执行，不能破坏本地顺序语义；7) 给出负载不均场景下与固定分配方案的完成时间对比数据；8) 测试覆盖窃取正确性、任务不重不漏、动态增删线程、异常隔离、依赖顺序与负载对比；`mvn -q verify` 一条命令跑通。
